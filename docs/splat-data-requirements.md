# 3DGS データへの修正依頼

このドキュメントは、3DGS データを作成いただいている方にそのままお渡しできるよう書いています。

---

## 1. お願いしたいこと（要約）

**splat のスケール（大きさ）を、現状の 1.5 倍以上にしてください。**
splat の数・位置・色・回転は変更不要です。スケール値だけを一律で大きくしていただければ結構です。

判定用のツールを同梱しています。出力の「判定」が **良好** または **許容** になればOKです。

```
node tools/check-splat-coverage.mjs <ファイル>
```

---

## 2. 症状

ビューアで表示すると、**表面に細かい亀裂状・斑点状の抜け**が出ます。抜けた部分は背景が透けます。

顔や肌など、本来は滑らかであるべき面に、ひび割れのような細い線が網目状に走ります。
一部のファイルでのみ発生します。

---

## 3. 原因

**隣り合う splat の間隔に対して、splat が小さすぎます。**

3DGS はガウシアン（ぼやけた楕円）を重ねて面を作ります。隣どうしが十分に重ならないと、
その隙間から背景が透けます。

いただいたファイルの実測値です。

| 項目 | 実測値 |
|---|---|
| splat 数 | 351,605 |
| splat の面内サイズ σ（中央値） | 7.94e-4 |
| **最近傍の splat までの距離 / σ** | p50 = 1.30 / **p90 = 1.51** / p99 = 1.62 |

隣まで平均 1.3σ、1割の splat は 1.5σ 以上離れています。
**この距離が 1.0σ 以下でないと面が塞がりません。**

### 検証

同じファイルのスケールだけを変えて描画し、背景の透け具合を測定しました（顔の中央部 240×250px）。

| 条件 | 最近傍距離/σ (p90) | 平均透過率 | 10%以上透けた画素 | 見た目 |
|---|---|---|---|---|
| **σ × 1.0（現状）** | **1.51** | **2.5%** | **6.3%** | **亀裂がはっきり見える** |
| σ × 1.5 | 0.97 | 0.1% | 0.0% | 亀裂が消える |
| σ × 2.0 | 0.73 | 0.0% | 0.0% | 亀裂が消える |

σ を 1.5 倍にするだけで抜けは解消します。位置も数も変えていません。

---

## 4. 修正方法

### A案：スケールを一律で大きくする（推奨）

全 splat のスケール 3 成分を **1.5 倍以上**にしてください。

- `.splat` 形式：オフセット 12〜23 バイトの float32 × 3 を 1.5 倍
- `.ply` 形式：`scale_0` / `scale_1` / `scale_2` は**自然対数**で入っているため、
  各値に `ln(1.5) ≒ 0.405` を**加算**してください（乗算ではありません）

ファイルサイズ・描画負荷は変わりません。ディテールがごくわずかに柔らかくなります。

### B案：splat を増やして間隔を詰める

密度を 2.3 倍（351,605 → 約 80 万個）にすれば、σ はそのままで面が塞がります。
ディテールは保てますが、**ファイルサイズと描画負荷が 2.3 倍**になります。
低スペック端末や VR での利用を考えると A案を推奨します。

### C案：生成パイプライン側での対応

深度マップから splat を生成している場合、各 splat のサイズが
「そのピクセルが担当する面積」ちょうどに設定されている可能性があります。
面が斜めを向いている箇所ほど実際の間隔が広がるため、
**サイズに 1.5〜2 倍の余裕（オーバーラップ）を持たせる**設定にしてください。

---

## 5. 効果がない対策（試さないでください）

こちらで検証済みです。時間を使わないようご注意ください。

| 対策 | なぜ効かないか |
|---|---|
| **モデル全体の拡大・縮小** | 距離も σ も同じ倍率で変わるため、比が変わりません。数学的に効果ゼロです |
| **ファイル形式の変更**（.ply ↔ .splat ↔ .spz） | ビューア内部では同じ表現に変換されるため無関係です |
| **座標の精度を上げる**（float64 で書く等） | 位置を float32 で保持する高精度モードで描画しても、亀裂は**まったく変化しませんでした**（画素差の最大 8.6%、97.8% の画素で差 2% 以下） |
| **不透明度を上げる** | 抜けは「面の穴」であり、不透明度では埋まりません。すでに 93% の splat が不透明度 255（最大）です |
| **splat の回転を調整する** | 抜けは間隔と大きさの関係で決まります |

---

## 6. 受け入れ基準

同梱ツールで検査し、**最近傍距離 / σ の p90 が 1.0 以下**になっていることを確認してください。

```
$ node tools/check-splat-coverage.mjs your-file.splat

  最近傍距離 / σ    p50 = 0.68   p90 = 0.97   p99 = 1.11
  ★ 判定 (p90 基準) : 良好 — 面がしっかり塞がる
```

| p90 | 判定 |
|---|---|
| ≦ 1.0 | 良好（面がしっかり塞がる） |
| ≦ 1.2 | 許容（ほぼ塞がる） |
| ≦ 1.5 | 注意（条件によっては抜けが見える） |
| > 1.5 | 破綻（亀裂状・斑点状の抜けが出る） |

ツールは `.splat` と `.ply`（binary_little_endian）に対応しています。

---

## 補足：位置の量子化について

ツールは参考値として「位置の float16 量子化誤差 / σ」も表示します。
本ビューアが使う描画エンジンは splat の位置を float16 で保持するため、
モデルの広がりに対して splat が極端に小さいと、位置が格子に吸着して
別の斑点が出ることがあります。

いただいたファイルではこの値は 0.359 で、**今回の亀裂の原因ではありません**
（高精度モードで描画しても亀裂は消えませんでした）。0.5 を大きく超えるようなら
併せてご相談ください。
